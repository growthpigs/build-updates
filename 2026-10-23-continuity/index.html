Why this plan exists

Cover for a complex, live system

War Room is a live, enterprise-scale system: three environments, three databases and more than 20 outside services, running for clients every day. Covering for Roderic takes a qualified senior engineer and a ramp-up period.

  • The contract covers the legal side: accounts in Think Big's name, daily commits to Think Big repos, and a handoff on exit
  • This plan covers the practical side: what that engineer needs to take over safely
  • On 20 October Carlos asked Roderic to write it as part of Corgi, for sign-off on Tuesday 10 November

Who the documents are for
A senior engineer. The architecture overview and the step-by-step guides are written for an experienced engineer stepping in, not for non-technical staff.

With a ramp-up period. Even with good documents, a newcomer needs time to learn a system of this size before changing it safely.

What Think Big holds in the meantime: the code, the accounts and the keys in its own name, so that engineer can be given access on day one.

Part 1 · the code in Think Big's name · where it stands

The code moved, and came back the same day

On 22 October the War Room repo moved to Think Big's GitHub organisation, Think-Big-Media. That organisation is on GitHub's free plan, which does not allow branch protection on private repos, so the required quality checks switched off.

  • Roderic moved the repo back to growthpigs the same day
  • Everything was checked afterwards: code, history, keys, build machines and hosting all intact done
  • The required quality checks were switched back on the same day done
Next step: a decision for Think Big
Upgrade Think-Big-Media to GitHub Team. It is paid per member per month, and the organisation has about 4 members today.

Then we redo the move, check the quality checks came across, and re-connect hosting to the new home.

Until then the code stays on growthpigs, with its quality checks on. The 3 November target for part 1 depends on this upgrade. waiting on Think Big
What the covering engineer inherits · first inventory, read from the code

What War Room runs on

GitHub
The War Room code, plus this reports site. Today on Roderic's account.
Netlify · 3 sites
The web app: test, staging and production (app.thewarroom.ai).
Render · 3 services
The back end, split across two workspaces: one on Roderic's account, one on Think Big's.
Neon · 3 databases
One each for test, staging and production.
Cloudflare
File storage and the gateway service. On Roderic's account.
Sentry
Error reports. Already in Think Big's organisation.
Outside vendors
AI models (OpenAI, OpenRouter, Perplexity and others), news and search data (GNews, NewsAPI, DataForSEO, KIE, Apify, Mentionlytics), ads data from Google and Meta, plus email, SMS and alerts. The register will say whose account each is on.
Keys War Room makes for itself
Sign-in, encryption and internal access keys. They are copied into the Think Big vault. Changing them signs everyone out, so that is a planned window, never a side effect.
Beyond accounts and keys

What a successor would need provided

These run on Roderic's side today. For each, the plan says how a covering engineer gets it: handed over to Think Big, or a documented replacement they can set up.

Roderic's build machines planned
The machines that run most of the automatic tests and release steps. One option: GitHub's own machines inside the Think Big organisation.
Our automated review checks planned
The extra review every change passes before release. It runs from Roderic's own tooling today.
The gateway service planned
A small service most operations go through, on Roderic's Cloudflare account.
Alerting planned
The alerts that page someone when something breaks, and the automatic sorting of incoming reports. Plus copies of keys kept on Roderic's own machines, which move into the vault.
